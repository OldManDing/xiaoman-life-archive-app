## 三、App 用户端问题

### A1【P0】时间轴把"没加载到"显示成"没有记录"

**现象**：时间轴只请求第 1 页 40 条，却对未加载的年份给出"没有记录"的肯定结论。
实测：点选 2023 年 → 页面显示 **"2023年还没有记录。"**，而接口中 2023 年确实有 20 条记录。

**证据**：`apps/web/src/pages/home-pages.tsx:885-886`

```ts
page: 1,
page_size: 40,
```

**影响**：用户会认为自己的档案丢了。这不是"翻不到"，而是**主动给出了错误结论**，属于信任级损害。

**验证**：已实跑（`22-emu-timeline-2023.png`）

**建议**：接入分页（后端 `listRecords` 已支持 `page` / `start_time` / `end_time`），并在未加载时显示"加载更多"而不是"还没有记录"。

---

### A2【P0】年份筛选硬截断为 4 个，且被空年份占用

**现象**：实测只出现 `2026 暂无`、`2025 20条`、`2024 20条`、`2023 暂无`。
有数据的 **2022 / 2021 / 2020 连入口都没有**；4 个位置里还被"当前年份 2026"和"未加载的 2023"占掉两个。

**证据**：`apps/web/src/pages/home-pages.tsx:916`

```ts
...Array.from({ length: 4 }, ...)).sort(...).slice(0, 4);
```

**验证**：已实跑

**建议**：取消 `slice(0, 4)`，改为横向滚动；年份来源应以"实际有数据的年份"为准。

---

### A3【P0】时间轴首屏默认是空的

**现象**：默认选中当前年份（2026），而 2026 无记录 → 一进时间轴就是一大片"2026年还没有记录"。
同一份档案：**首页显示 50 条，时间轴显示 0 条**，两个页面给出相反印象。

**证据**：`apps/web/src/pages/home-pages.tsx`（默认年份取当前年）+ `:1143-1147`（空态渲染）

**验证**：已实跑（`21-emu-timeline.png`）

**建议**：默认选中"最近有记录的年份"；完全无记录时才显示真正的空态。

### A4【P0】只读成员能看到"编辑记录 / 删除记录"

**现象**：以奶奶（viewer）身份打开爸爸创建的记录，「编辑记录」和「删除记录」都在，且「编辑记录」是主按钮样式。

**根因**：会话对象里没有家庭角色字段，前端在结构上无法按角色收敛按钮。

**证据**：
- `apps/web/src/pages/record-pages.tsx:3341-3350`（无条件渲染）
- `apps/web/src/shared/api/types.ts` 的 `UserProfile` 只有 `membership_type`，无 `family_role`
- 服务端规则：`apps/api/src/shared/services/access-control.service.ts:132-143`

**验证**：已实跑（`23-emu-record-detail.png`）
**未验证**：viewer 点击保存后被服务端 403 的具体表现（后端未运行）

**建议**：登录/会话接口下发 `family_role`；viewer 不渲染这两个按钮。

**现象**：空表单点「发布」→ 弹窗 **"发布前请填写标题"**，无法只发一张照片。

## 四、后端 API 问题

> 本节**全部为静态审读**。本机无 Docker / MySQL / Redis / MinIO，未启动过服务，未执行 Prisma 迁移。

### B1【P0】原生 App 无法从仓库重建

**现象**：`apps/mobile/android` 整个原生工程被 `.gitignore` 忽略，不在版本库内；而 `scripts/prepare-mobile-web.cjs` 是往该目录里**手工改过的 `MainActivity.java`** 打补丁（要求匹配 `super.onCreate(savedInstanceState);`）。

Capacitor 7 全新脚手架生成的是空的 `extends BridgeActivity {}`，没有这行 → 脚本直接抛错：

```
Error: Unable to register NativeLocationPlugin in .../MainActivity.java
```

**影响**：**换一台机器或换一个人，都构建不出他们的 APK。** 原生工程只存在于某个人的磁盘上，且包含未入库的手工修改（位置、更新、华为推送等插件注入点）。

**验证**：跨机器重建时已实测报错（本次为绕过该问题，用了标准 MainActivity，未注入原生插件）

**建议**：把 `apps/mobile/android` 纳入版本库，或补齐一套可重复的 `cap add android` + 插件注入脚本。这是**发布阻断级**问题。

### B3【P1】"月报"从未实现，不是"暂停"

**现象**：`schema.prisma` 中**没有 `MonthlyReport` 表**（PRD `:687` 定义了该模型），只有 `AiJobType.monthly_report` 枚举值，且**全仓没有任何入队调用点**；fallback 直接返回固定字符串。

**证据**：
- `docs/孩子的人生档案馆_prd_v_1.md:687`（PRD 定义）
- `apps/api/prisma/schema.prisma`（无该模型）
- `apps/api/src/modules/ai-jobs/ai-provider.service.ts:67-68`
  ```ts
  case AiJobType.monthly_report:
    return { summary: '本月成长月报已生成。' };
  ```
- `apps/web/src/pages/profile-pages.tsx:1067`（ReportsPage 是拿上个月记录现算计数 + 拼接文案的演示页）

**结论**：所谓"暂停月报"的真相是——它从来就是一个演示页，不是一个功能。

### B4【P1】没有任何"回忆触发"定时任务

**现象**：全仓定时器只有三处 `setInterval`，均为基础设施用途：

| 位置 | 用途 |
|---|---|
| `apps/api/src/modules/ai-jobs/ai-jobs.queue.ts:23` | AI 任务恢复轮询 |
| `apps/api/src/shared/services/huawei-push-delivery.service.ts:42` | 推送投递重试 |
| `apps/api/src/shared/services/audit-log.service.ts:33` | 审计日志清理 |

唯一的通知类型是 `family.record_published`（"家人发了一条记录"）。

**影响**：PRD 明确要求"必须通过月报、纪念册、**回忆提醒**等机制持续输出真实价值"。当前产品**没有任何主动召回用户的钩子**，留存完全依赖"别人又传了一张"。

这是产品层面**投入产出比最高**的缺口：推送链路已经跑通，只缺一个定时任务。

### B5【P1】队列是进程内轮询，不是 BullMQ；Redis 装了没用

**现象**：`apps/api/package.json` 声明了 `bullmq`、`ioredis`、`@nestjs/bullmq`，但**源码中一处都没有 import**（全量扫描确认）。`ai-jobs.queue.ts` 实际用的是 `setInterval` 轮询 `ai_jobs` 表。

**验证**：依赖扫描确认（`未使用: bullmq / ioredis / @nestjs/bullmq`）

## 附录 A：安卓模拟器复现步骤

本次审查从零搭建了工具链（本机原本无 SDK / JDK / 模拟器）。

```powershell
# 1. 工具链
#    Temurin JDK 21 + Android commandline-tools
#    sdkmanager "platform-tools" "emulator" "platforms;android-35"
#               "build-tools;35.0.0" "system-images;android-35;google_apis;x86_64"

# 2. 创建模拟器
avdmanager create avd -n nianlun -k "system-images;android-35;google_apis;x86_64" -d pixel_6
emulator -avd nianlun -no-snapshot -no-boot-anim -gpu swiftshader_indirect

# 3. 构建 APK（注意：需要绕过 B1 描述的插件注入失败）
vite build                                    # apps/web -> dist
node scripts/prepare-mobile-web.cjs            # dist -> www
npx cap add android                           # 生成 apps/mobile/android
gradlew assembleDebug                         # 需代理，Gradle 自身下载器不走系统代理

# 4. 安装与驱动
adb install -r app-debug.apk
adb shell am start -n com.xmlga.nianlun/.MainActivity
adb forward tcp:9223 localabstract:webview_devtools_remote_<pid>
# 之后通过 CDP 在真实 WebView 内执行断言
```

**踩到的坑（供复现者参考）**

| 现象 | 原因 | 解决 |
|---|---|---|
| `Could not find installation of TypeScript` | `cap` 需要 TS 解析 `capacitor.config.ts` | 安装 TypeScript 5.x（**7.x 不兼容**，报 `Cannot read properties of undefined (reading 'CommonJS')`） |
| `npm.cmd is not recognized` | `prepare-mobile-web.cjs` 内部调用 npm | 需提供 npm，或预先手动构建 dist |
| Gradle 下载超时 | wrapper 不读系统代理，且超时仅 10s | 手动下载并校验 sha256 后投放进 `~/.gradle/wrapper/dists` |
| 依赖下载卡死 | JVM 不走 Windows 系统代理 | `~/.gradle/gradle.properties` 加 `systemProp.https.proxyHost/Port` |
| 脚本抛 `Unable to register NativeLocationPlugin` | 见 B1，脚手架 MainActivity 与脚本假设不匹配 | 本次改用标准 MainActivity，未注入原生插件 |

## 结语

**这个项目最可惜的地方不是代码，代码是它最强的部分。** 数据模型（25 张表）、权限模型（owner/editor/viewer）、审计与内容风险、安全默认值（严格环境禁用 mock、占位密钥启动期报错、坐标脱敏、预签名 URL）——这些都接近可长期运行的水准。

最可惜的是：一个想清楚"档案而非相册"的产品，交付出来的是一个精致的相册。工程力气花在了把它做"稳"和做"全"（后台 41 个端点，比用户侧 21 个还多），却没有花在把它做"留得住"。

而缺的东西大多不需要重写：导出工单、通知与推送、AI 任务队列、`listRecords` 的分页参数全都在，缺的是**几个决定**——把哪些功能真正放出来，以及首页要不要变回"档案"的样子。
